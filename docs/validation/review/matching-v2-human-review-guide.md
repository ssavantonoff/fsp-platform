## Проверяющему: цель и материалы

Цель — независимо оценить профессиональную релевантность синтетических кандидатов
конкретным позициям до просмотра любых алгоритмических результатов или ранее
предложенных оценок. Это исследование на небольшом проверочном датасете, а не
решение о найме реальных людей и не подтверждение качества Matching V2.

Координатор передаёт только три файла из этого каталога:

1. Эту инструкцию.
2. `matching-v2-human-review-input-v1.csv` — профессиональные данные по 38 парам.
3. Отдельную личную копию `matching-v2-human-review-template-v1.csv` — пустой бланк.

Не открывайте исходный репозиторий, AI proposals, их обоснования или результаты
Matching до сдачи независимого бланка. Не обсуждайте оценки со вторым проверяющим
до завершения обеих независимых проверок. Если ранее видели такие подсказки,
сообщите координатору: это ограничение независимости, которое нужно зафиксировать.

## Что содержится в input

Каждая строка относится к одной паре `need_id` + `candidate_id`. Порядок — сначала
Need ID, затем Candidate ID. Это нейтральный порядок идентификаторов, не рейтинг.
Идентификатор обозначает запись только внутри `matching-v2-validation-v1`.

| Need: CSV-поле | Смысл |
| --- | --- |
| need_id | Идентификатор позиции N1–N8 |
| position_title | Название конкретной позиции |
| need_specialization | Направление позиции |
| required_grade | Требуемый грейд |
| must_have_skills | Обязательные skill tags |
| nice_to_have_skills | Желательные skill tags |
| target_experience_years | Мягкий ориентир опыта в годах |
| description | Описание работы из frozen dataset |
| catalog_proxy | CATALOG_PROXY для позиций с ограничением каталога; иначе пусто |
| catalog_limitation | Явное описание отсутствующих в каталоге компетенций |

| Candidate: CSV-поле | Смысл |
| --- | --- |
| candidate_id | Синтетический идентификатор C01–C36 |
| candidate_specialization | Направление кандидата |
| verified_grade | Канонический verified grade из синтетического fixture |
| normalized_assessment_score | Синтетический нормализованный Assessment score |
| skills | Self-declared skill tags |
| years_of_experience | Self-declared общий стаж в годах; пусто означает неизвестно |

Списки навыков записаны как JSON-массив внутри CSV-ячейки: кавычки и запятые —
часть формата, а не дополнительные навыки. `[]` означает пустой список.
Неизвестный стаж не является нулевым. Общий стаж не подтверждает опыт в конкретном
стеке, релевантные проекты, архитектуру, лидерство или индивидуальный вклад.

CSV имеет UTF-8 без BOM, разделитель — запятая, все ячейки заключены в кавычки.
При импорте в табличный редактор явно выберите UTF-8 и запятую; не разбивайте строки
вручную. Внутри description возможны запятые, кавычки и переводы строк: они должны
оставаться внутри одной ячейки. Не меняйте input и идентификаторы в бланке.

## Как оценивать и заполнять бланк

Оценивайте соответствие доступных профессиональных свидетельств конкретной работе:
specialization, verified grade, обязательные/дополнительные skill tags, Assessment
evidence и возможную релевантность опыта. Не вычисляйте взвешенную формулу и не
пытайтесь угадать порядок, который выдаст алгоритм. Стаж или более высокий
совместимый grade не дают автоматического преимущества либо штрафа.

FSP achievements в профессиональную оценку не входят и в input не показываются.
Declared grade, AI grades/rationales, Professional Fit, Ranking Score, production
order, контакты и приватные идентификаторы также не предоставлены.

| reviewer_grade | Профессиональная релевантность внутри допущенного пула |
| --- | --- |
| 0 | Низкая релевантность |
| 1 | Частичное соответствие |
| 2 | Хорошее соответствие |
| 3 | Очень хорошее соответствие |

Для каждой пары самостоятельно заполните:

- `reviewer_grade`: одно целое число 0, 1, 2 или 3.
- `reviewer_rationale`: короткое объяснение, какие профессиональные факты привели
  к оценке именно для этой позиции.
- `reviewer_uncertainty`: какие данные отсутствуют, неоднозначны или ограничивают
  уверенность. Не добавляйте предполагаемые проекты и компетенции как факты.

Одинаковые оценки допустимы. Не создавайте искусственное полное ранжирование и не
обязаны использовать каждое значение шкалы. Неизвестная компетенция не равна
доказанному отсутствию компетенции. Если оценить пару невозможно, оставьте grade
пустым и объясните причину в uncertainty; такая пара считается незавершённой и
нуждается в обсуждении. Не ставьте фиктивный 0 только ради заполнения всех строк.

В исходном бланке все три reviewer-поля пусты. Их должен заполнить реальный
проверяющий. Не поручайте выставление оценок AI, скрипту или subagent. Сохраните
заполненную копию в UTF-8; координатор сохранит её отдельно от исходного шаблона.

## Ограничения Assessment и заявленных данных

Датасет полностью синтетический. Verified grade/score здесь — канонические
fixture-входы, а не наблюдавшиеся результаты реальных попыток Assessment.
В текущей базе нет production question bank для FRONTEND и DATA_ML; их канонические
Assessment сведения являются offline fixtures. И для Backend нет ответов или
детализации выполненных заданий в этом пакете.

Нельзя напрямую считать одинаковые scores разных grades или направлений
измерением одинаковой квалификации: психометрическая эквивалентность не доказана.
Score — ограниченное свидетельство в контексте verified grade. Skill tags и стаж
self-declared, не подтверждены портфолио, заданиями, references или проектами.
Человеческая оценка не превращает отсутствующие свидетельства в подтверждённые.

`111e1a06f2a57e6c1194ce1dd5cf75e3f275cefda38de662d0bb7a0b2d6dd6ed`.

Generator читает оба frozen inputs без записи; только dataset парсится. Он
самостоятельно применяет утверждённые hard filters и проверяет reference counts,
без production imports, Matching/scoring, ranking order или AI label projection.
Проверки hashes выполняются до создания output. При несовпадении — STOP.
Автоматическое исправление frozen файла, newline/encoding или Git config запрещено.
На Windows checkout может заменить LF на CRLF; одинаковое содержимое JSON и clean
git status не доказывают совпадения byte SHA256. Восстановление exact Git blob
требует отдельного разрешения, если local bytes изменены.

Из корня репозитория с существующим Python 3.13+ и repository test dependencies:

```powershell
backend\.venv\Scripts\python.exe -X utf8 backend/prepare_matching_v2_review.py --check
backend\.venv\Scripts\python.exe -X utf8 -m pytest --noconftest --basetemp=.cache/review-gate-tests -q backend/tests/test_matching_v2_review.py
backend\.venv\Scripts\python.exe -X utf8 -m ruff check backend/prepare_matching_v2_review.py backend/tests/test_matching_v2_review.py
backend\.venv\Scripts\python.exe -X utf8 -m ruff format --check backend/prepare_matching_v2_review.py backend/tests/test_matching_v2_review.py
backend\.venv\Scripts\python.exe -X utf8 -m mypy backend/prepare_matching_v2_review.py
```

`--check` не пишет файлы. Без него script создаёт только два фиксированных CSV;
уже существующие эквивалентные CSV не перезаписываются, отличающиеся по ячейкам или
заполненные человеком файлы вызывают отказ. Новый output допускается только в этом review
каталоге либо внутри repository `.cache`; symlink targets запрещены. Guide не
перезаписывается generator. Генерация CSV детерминированна: UTF-8/LF без BOM.
Git checkout может изменить только разделители записей на CRLF: `--check` сравнивает
все ячейки, схему и порядок записей через CSV parser, не меняя файл. Переводы строк
внутри ячеек сохраняются точно; изменение description не считается эквивалентным.
Выводимый hash относится к фактическим байтам output. Frozen JSON hashes остаются
строго побайтовыми. Tests покрывают byte reproducibility генерации, CSV escaping,
CRLF/LF record equivalence без записи и отказ при изменённых ячейках.
