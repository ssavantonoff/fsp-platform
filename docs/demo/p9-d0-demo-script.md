## Для Савелия: запись примерно на 6 минут 30 секунд

### A. ЧТО ПОДГОТОВИТЬ ДО ЗАПИСИ

#### 1. Запустить приложение

Если приложение уже работает, перейти к пункту 2. Иначе попросить технического участника
выполнить [инструкцию запуска](p9-d0-local-run-guide.md) в новой отдельной копии проекта.
Не использовать и не изменять рабочие копии P9-A0/P9-B0/P8-B0/P8-B1/fsp-platform-manual.

Основные команды для MacBook, если порты 3000, 8000, 5432 свободны:

```sh
git clone https://github.com/ssavantonoff/fsp-platform.git fsp-platform-demo
cd fsp-platform-demo
git checkout bce395a8c102491f4cf9ac26106b7263d08ad515
cp .env.example .env
```

Технический участник задаёт свои локальные пароли в `.env` по инструкции запуска.
Пароли и этот файл в видео не показывать.

```sh
docker compose -p fsp-p9-d0-demo up --build -d --wait
docker compose -p fsp-p9-d0-demo exec backend python -m app.seed --demo
docker compose -p fsp-p9-d0-demo exec backend python -m app.seed --matching-demo
```

Каждая команда добавления демонстрационных данных должна закончиться `Seed completed.`.
Если этого нет, перейти к разделу D. Для всей записи адрес приложения —
**http://localhost:3000**. При других портах заранее заменить адреса во всех закладках.

#### 2. Подготовить два отдельных входа

Использовать два разных профиля браузера или два разных браузера.
Две обычные вкладки одного профиля используют один вход и не подходят для двух ролей.

- Окно кандидата: http://localhost:3000/login → `candidate@example.com` → «Войти».
- Окно работодателя: тот же адрес → `employer@example.com` → «Войти».
- Пароль — собственный `DEMO_PASSWORD`, заданный командой до добавления аккаунтов.
  Входы завершить до начала записи. Пароль не произносить и не показывать.

Аккаунты синтетические. После первого добавления их email уже подтверждены.
Повторное добавление данных сохраняет существующие профили и пароли.

#### 3. Подготовить профиль кандидата

В окне кандидата открыть http://localhost:3000/candidate/edit.
Сохранить специализацию Backend, заявленный Middle, опыт 3 года,
навыки Python/FastAPI/PostgreSQL/Django, FSP ID `MOCK-MULTI` и согласие на обработку данных.
Нажать **«Сохранить профиль»**. Не менять специализацию во время активного теста.

Открыть http://localhost:3000/candidate и в «Достижения ФСП» нажать
**«Проверить FSP ID»**. Ожидаются три достижения и отметка «MOCK / прототип».
Это демонстрационные достижения ФСП из тестового реестра, **не официальное API ФСП**.

#### 4. Заранее пройти настоящее профессиональное тестирование

Выделить до 30 минут отдельно от записи. Этот шаг нельзя заменить демонстрационной оценкой.

1. Открыть http://localhost:3000/candidate/assessment.
2. Нажать «Выбрать Middle», прочитать правила, затем «Начать тест».
3. Самостоятельно ответить на 20 вопросов. После каждого выбора дождаться сохранения;
   переходить кнопкой «Далее». Галочка у номера обозначает сохранённый ответ.
4. Нажать «Завершить тест», затем ещё раз «Завершить тест» в подтверждении.
5. Проверить «Попытка успешно пройдена», балл, результаты по разделам и текущую квалификацию.
   Успех требует ≥70/100 и ≥50% в каждом из пяти разделов; он не гарантируется.
6. Сохранить фактическую страницу `/candidate/assessment/<attemptId>` в закладки.
   `attemptId` берётся из адреса созданной попытки, его нельзя придумать.
   Позже результат доступен в http://localhost:3000/candidate/assessment/history → «Результат».

**У `candidate@example.com` после обычного добавления данных нет подтверждённого уровня и
нет завершённой попытки. Другим кандидатам в демонстрационном пуле заранее заданы уровень и
балл, но история настоящего тестирования для них не создаётся. Их оценки нельзя выдавать
за результат действительно пройденного теста.** Это установлено исходниками `app.seed`
и отдельной HTTP-проверкой P9-D0.

Если Middle не пройден, повтор на этом уровне — через 7 дней. Можно пройти Junior, если
приложение разрешает выбор. Тогда подготовить через http://localhost:3000/employer/needs/new
новую заявку на Junior по рецепту ниже, активировать и использовать её настоящий
адрес вместо стандартной заявки Middle. Если успешного теста нет, обязательный кадр ещё не готов.
Не менять оценки, сроки или данные попыток вручную. Не брать ключи ответов из исходников.

#### 5. Подготовить заявку работодателя

В окне работодателя открыть http://localhost:3000/employer/needs.
Найти **Backend Python Engineer**, статус «Активна», нажать **«Подбор кандидатов»**.
Стандартный адрес:

http://localhost:3000/employer/needs/demo-need-backend-middle-active/matches

В списке должен быть **Алексей И.** — аккаунт `candidate@example.com` после реального
успешного Middle и добавления FastAPI. Место/баллы зависят от результата теста;
первое место или 100/100 не обещать.

Стандартная заявка: Backend/Middle, 3 года, обязательные Python/FastAPI,
желательные PostgreSQL/Django, зарплата 180000–260000 ₽ до вычета налогов.
Если выбрана новая Junior-заявка, записать её ID и ссылки из браузера заранее.

#### Как создать отдельную заявку для репетиции, новой записи или Junior-варианта

Это обычная форма приложения; работа с базой данных не нужна.

1. В окне работодателя открыть http://localhost:3000/employer/needs/new.
2. «Позиция»: ввести `Демонстрация CodexTeam — запись` (для репетиции — `Демонстрация CodexTeam — репетиция`).
3. «Специализация»: Backend. «Требуемый уровень»: Junior после успешного Junior-теста;
   Middle для основного подготовленного кандидата или репетиции с Марией.
4. «Описание потребности»: `Ищем специалиста для демонстрационного проекта на Python и FastAPI.`
5. «Целевой опыт, лет»: 3. «Обязательные навыки»: Python и FastAPI.
   «Желательные навыки»: PostgreSQL и Django; не выбирать один навык в обеих группах.
6. «Зарплата от»: 100000. «Зарплата до»: 150000. Это вымышленные условия демонстрации,
   не настоящее предложение работы. «Дополнительные требования» можно оставить пустыми.
7. Нажать «Создать потребность». Дождаться сохранения; откроется страница редактирования новой заявки.
8. Открыть http://localhost:3000/employer/needs, найти введённую позицию → «Активировать».
9. Дождаться «Активна» → «Подбор кандидатов». Сохранить фактический адрес из браузера.
   По ссылке «Приглашения» сохранить второй адрес этой же заявки.

Для повторной записи создавать новую заявку, а не редактировать уже использованную:
у приглашения остаётся связь с прежней заявкой. Везде в сценарии использовать сохранённые
адреса новой заявки, не адрес стандартной Middle-заявки.

#### 6. Оставить основное приглашение для записи

Не отправлять основное приглашение на репетиции. Для полной проверки отправки/принятия
создать отдельную заявку по рецепту выше и использовать её только для репетиции.
Для записи должна остаться новая пара «заявка — кандидат» без старого открытого или принятого
приглашения. Повторное добавление демонстрационных данных приглашения не сбрасывает.

#### 7. Подготовить изображение и звук

Запись делает Савелий на MacBook самостоятельно. Предпочтительно MP4/H.264/AAC,
1920×1080 или выше, 5–7 минут. При невозможности — сохранить читаемый интерфейс и указать
фактическое разрешение. Голос желателен; допустимы короткие текстовые подписи.
Закладки и входы подготовить заранее. Не показывать `.env`, пароли, коды подтверждения,
cookies, токены или реальные персональные данные. Не подменять интерфейс изображениями.
Ошибка не должна исчезать в монтаже так, будто действие успешно завершилось.
Файл хранить вне Git; координатор отдельно передаст ссылку или файл.

#### 0:00–0:30 — Что делает платформа

- **Куда зайти:** http://localhost:3000/
- **На какую кнопку нажать:** никакую; показать главную.
- **Что должно появиться:** главная страница FSP Platform.
- **Что сказать:** «Это FSP Platform — платформа для подтверждения квалификации и подбора подходящих кандидатов. Все люди, компании и данные в этой демонстрации вымышленные».

#### 0:30–1:20 — Результат профессионального тестирования

- **Куда зайти:** в окне кандидата открыть закладку настоящей успешной попытки.
- **На какую кнопку нажать:** если открыта история, «Результат» у этой попытки.
- **Что должно появиться:** «Попытка успешно пройдена», балл, результаты по разделам и текущая квалификация.
- **Что сказать:** «Кандидат заранее прошёл профессиональное тестирование — Assessment — через приложение. Здесь показаны его настоящий результат и подтверждённый уровень; уровень, который человек сам указал в профиле, отображается отдельно».

Назвать только фактический балл и уровень с экрана.

#### 1:20–2:00 — Демонстрационные достижения ФСП

- **Куда зайти:** http://localhost:3000/candidate, прокрутить до «Достижения ФСП».
- **На какую кнопку нажать:** никакую, если достижения подготовлены.
- **Что должно появиться:** три достижения, отметка «MOCK / прототип» и предупреждение о тестовом реестре.
- **Что сказать:** «Это демонстрационные достижения ФСП из тестового реестра. Они не получены через официальное API ФСП: здесь мы показываем, как такой источник достижений учитывается в прототипе».

#### 2:00–2:40 — Заявка работодателя на специалиста

- **Куда зайти:** окно работодателя, http://localhost:3000/employer/needs.
- **На какую кнопку нажать:** «Подбор кандидатов» у выбранной активной заявки.
- **Что должно появиться:** требования и подходящие кандидаты.
- **Что сказать:** «Работодатель задаёт, какой специалист ему нужен: направление, уровень и обязательные навыки. Система сначала проверяет, кто соответствует этим условиям».

#### 2:40–3:35 — Подбор подходящих кандидатов

- **Куда зайти:** остаться на странице подбора, показать несколько карточек.
- **На какую кнопку нажать:** никакую; плавно прокрутить список.
- **Что должно появиться:** порядок кандидатов, `Professional Fit`, `Ranking Score` и вклад достижений.
- **Что сказать:** «Кандидаты упорядочены по рассчитанному соответствию заявке. Основную часть итоговой оценки составляет профессиональное соответствие, а достижения из тестового реестра ФСП могут добавить до пяти баллов».

Не заявлять, что качество подбора подтверждено независимыми человеческими оценками.

#### 3:35–4:25 — Почему система рекомендует кандидата

- **Куда зайти:** найти карточку «Алексей И.» на этой странице.
- **На какую кнопку нажать:** «Почему такой результат».
- **Что должно появиться:** результат тестирования, уровень, желательные навыки, опыт и вклад факторов.
- **Что сказать:** «Рекомендацию можно объяснить: здесь видно, как на оценку повлияли тестирование, уровень, навыки и опыт. Контакты кандидата пока скрыты».

#### 4:25–5:05 — Отправка приглашения

- **Куда зайти:** остаться у карточки Алексея И.
- **На какую кнопку нажать:** «Пригласить» → сообщение «Демонстрационное приглашение CodexTeam» → «Отправить приглашение»; после успеха перейти по ссылке «Приглашения».
- **Что должно появиться:** «Приглашение отправлено», в истории «Отправлено»; контакта кандидата нет.
- **Что сказать:** «Работодатель отправляет предложение кандидату. До принятия приглашения контакт кандидата работодателю не раскрывается».

#### 5:05–5:50 — Принятие приглашения

- **Куда зайти:** окно кандидата, http://localhost:3000/candidate/invitations.
- **На какую кнопку нажать:** «Обновить» → «Открыть» у нужной заявки → «Принять».
- **Что должно появиться:** условия и сообщение; затем «Приглашение принято» и «Контакт работодателя».
- **Что сказать:** «Кандидат видит компанию и условия предложения и сам решает, принимать ли его. После принятия ему становится доступен контакт работодателя».

#### 5:50–6:30 — Раскрытие контактов после принятия приглашения

- **Куда зайти:** окно работодателя, http://localhost:3000/employer/needs/demo-need-backend-middle-active/invitations.
- **На какую кнопку нажать:** «Обновить».
- **Что должно появиться:** «Принято», «Контакт кандидата», вымышленное имя и `candidate@example.com`.
- **Что сказать:** «Теперь приглашение принято, и контакты доступны обеим сторонам. Мы показали путь от подтверждения квалификации до подбора специалиста и взаимного согласия на общение».

Для Junior или новой записи использовать настоящий ID своей подготовленной заявки во всех ссылках.

| Нет `Seed completed.` | Передать текст ошибки техническому участнику. Для `Assessment source differs from reviewed content` использовать LF-экспорт по инструкции запуска, не менять вопросы/оценки/БД |

| Алексей отсутствует в подборе | Через обычную форму проверить Backend, подходящий подтверждённый уровень, Python/FastAPI и согласие. Проверить активность заявки; обновить страницу |

| Нет приглашения у кандидата | Проверить `candidate@example.com`, позицию и «Обновить» |
| Нет контактов | Проверить «Принято» именно у нужного приглашения; обновить обе стороны |
| Ссылка подтверждения email не срабатывает | При подготовке нового аккаунта открыть свежую ссылку в новой вкладке или перезагрузить страницу. Код в видео не показывать |
| Ошибка в записи | Остановить, исправить причину и повторить честный показ. Для повторной отправки/принятия подготовить новую заявку через интерфейс |

## Полный сценарий: 18 шагов существующего приложения

Ориентир 30–50 минут, включая до 30 минут настоящего тестирования. Это расширенная
демонстрация для эксперта, не план короткой видеозаписи. Использовать новые синтетические
аккаунты, созданные штатно; примеры `p9demo.candidate@example.com` и
`p9demo.employer@example.com` **не создаются seed**. Если адрес уже существует, выбрать новый
синтетический адрес через регистрацию; не обещать заранее существующий аккаунт.
Локальная доставка подтверждения — журнал разработки, не реальная доставка письма.

## Точность сценария и ограничения для эксперта

- Подготовленные seed accounts существуют только после успешного seed. `candidate@example.com`
  имеет declared Middle, verified/score/date NULL, Python/Django/PostgreSQL без FastAPI.
- `match-exact@example.com`: синтетические Middle/90, 3 года, Python/FastAPI/PostgreSQL/Django;
  `match-senior@example.com`: Senior/100; `match-optional@example.com`: Middle/90,
  1.5 года, без Django; `match-no-experience@example.com`: Middle/90, опыт не указан.
  На свежем seed эти четыре участвуют в стандартном Middle-подборе.
- Остальные fixtures исключаются по несовместимому grade, missing must-have, verification,
  consent или specialization; они не заменяют настоящую попытку для видео.
- Допуск grade: Junior ← Junior/Middle; Middle ← Middle/Senior; Senior ← Senior.
  Профиль с Junior не попадёт в Middle-заявку даже при максимальном балле/достижениях.
- Professional Fit: Assessment 45%, уровень 25%, желательные навыки 15%, опыт 15%;
  отсутствующие параметры заявки выключают optional factors с нормализацией весов.
  Ranking Score = 0.95 × Professional Fit + FSP Bonus (0–5). Интерфейс округляет числа.
- Только Backend профессиональное тестирование опубликовано. Отдельная категория кандидата,
  публичный каталог вакансий/кандидатов, самостоятельные отклики, чат и уведомления
  приглашений по email не реализованы. Показ строится вокруг своей активной заявки.
- Human Review не проведён; Stage 2 не запускался. Механическая проверка формул не доказывает
  профессиональное качество рекомендаций. Не произносить human-validated, NDCG или hiring accuracy.
- Исторические результаты: [P9-A0 Draft PR #20](https://github.com/ssavantonoff/fsp-platform/pull/20)
  — настоящий браузерный путь, Junior PASS, отправка/принятие/контакты; новых P0/P1 нет,
  F01 P2 email fragment и F02 P3 unknown Need heading. [P9-B0 Draft PR #19](https://github.com/ssavantonoff/fsp-platform/pull/19)
  — 365/365 PostgreSQL PASS, 28/28 PR18 regressions, baseline CI SUCCESS.
  Это исторические результаты, не повторные проверки P9-D0 и не preflight MacBook.

Обязательные кадры видео: настоящий результат тестирования; порядок кандидатов;
объяснение рекомендации; достижения с явным раскрытием тестового источника;
отправка; принятие; контакты после принятия. До реального файла все поля видео остаются PENDING.
